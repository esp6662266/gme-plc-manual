# GME BC01 기반 설비 표준화

이 스킬은 해당 Git 저장소의 작업표준을 실행하는 진입점이다. 사용자 요청이 표준 작성/검토뿐이면 실제 설비 확장을 시작하지 않는다. “이어서 진행”이면 최신 저장 작업 기록에서 재개한다.

## 시작

1. Git 루트와 현재 변경을 확인한다. 루트 AGENTS.md → EXPANSION-WORK.md → VERSION.json/WORKSPACE-HANDOFF.md/PUBLICATION_STATUS.md → all-in-one/ACTIVE-WORK.md 최상단을 읽는다. 현재 원본은 all-in-one이며 옛 snapshot/dist/ZIP에서 작업하지 않는다.
2. 루트의 [작업표준](../../../docs/equipment-standard/WORK-STANDARD.md)과 [실행 안내](../../../docs/equipment-standard/START-GPT61.md)를 읽는다. 핵심 자료 위치/실행 위험은 [references/source-map.md](references/source-map.md)를 필요한 범위로 읽는다.
3. 스킬 scripts/preflight.py를 Python3.10+로 실행한다. 기본은 읽기 전용이며 생성기나 시험을 실행하지 않는다. 대장 불일치면 대상 배정 전에 원본 변경을 조사한다. source_byte_changes만 있고 대장이 같으면 변경 근거를 검토해 기록한다.
4. 요청 모델은 GPT-6.1 Sol / Ultra다. 스킬 텍스트가 현재 모델을 바꾸지는 않는다. 실제 선택/설정이 관측되면 기록하고 관측 불가면 미확인으로 쓴다.

## 한 작업 단위

- PREP-01 미완료면 공통화·금지 생성기 호출 분리·BC01 회귀를 먼저 진행한다. 그 후 FN04(P02) 시범 → 표준의 1차 순서 → 대장의 phase2를 진행한다.
- 23행과 248 ID를 합산하지 않는다. 기존 제외90과 2026-10-12 사용자 RO01~04 미사용예외4(총94), 다른 공정2, 제외 부모 하위 보류7을 유지한다. 2차 후보는 현재129이다. RO01/02 기존 원본·기록·게시이력은 보존한다. 대장이 바뀌면 실 ID로 재집계한다. “233개”를 맞추려고 ID나 완료 수를 만들지 않는다.
- WORK-ITEM-TEMPLATE.md로 설비 한 개의 목표·영향 파일·7영역 적용·원본 근거·검증·다음 작업을 기록한다.
- BC01의 깊이와 흐름을 재사용한다. 태그/알람/회로/36항목/제조사 정보를 다른 설비에 복제하지 않는다. 원본 XML·선언/핀·HMI·도면을 대조하고 미해석/후보/비해당을 명시한다.
- 부모만 공통 파일을 편집·통합한다. 최대2개 읽기 전용 조사/검토를 병행한다. 사용자 지시가 지속 작업이면 한 설비 검증·인계 후 다음 가능한 설비로 이어가며, 없는 현장 자료를 지어내거나 같은 보류를 반복 조사하지 않는다.

## 보존과 완료

- 시뮬레이터 작성·수정·생성·실행·행동 시험 금지. build-control-spec.py의 금지 호출 분리 전 실행 금지. 실제 PLC/현장/보호값, SEJIN 운영 자료를 변경하지 않는다.
- 원본·완료분·미지 필드·다른 설비 기록·초안·저장 키를 보존한다. 기록 도구는 해당 설비 지원이 구현되고 저장/재읽기/재열기까지 확인되어야 완료다.
- 변경에 맞는 정적/BC01 회귀/기록/UI/패키지 검사를 수행한다. verify:manual은 파일을 재생성한다. 문서만 변경하면 불필요한 매뉴얼 생성기를 돌리지 않는다.
- 문서·정적 검증·UI/기록·게시·TIA 컴파일·현재 CPU·현장 복구는 각각 상태로 남긴다. 현장 미확인을 문서 검사로 해결하지 않는다.
- EXPANSION-WORK.md와 설비 작업 기록을 실제 결과로 갱신한다. 코드 게시가 포함되면 버전·GitHub·Netlify 커밋과 게시 파일을 확인한다. 다음 작업 한 개와 필요한 자료를 인계한다.
