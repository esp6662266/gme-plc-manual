# GME 프로젝트 목적과 작업 기준

2026-10-07 사용자 확정: “지금의 프로젝트의 목적은 매뉴얼 및 수리와 프로그램 구조파악 및 개선이 목적이야.”

**최신 작업 범위:** “시뮬레이션은 내가 따로 작성하라고 하기전엔 작성하지마라.” 사용자가 별도로 작성을 요청하기 전까지 시뮬레이터 개발·수정·확장·행동 시험 재실행을 중지한다. 아래 최초 계획의 시뮬레이터 관련 내용은 보존한 계획이며 현재 실행 범위가 아니다. 매뉴얼·수리·원본 PLC 구조 분석·개선 검토는 계속 진행한다.

전체 설비에 대해 매뉴얼, 고장 진단과 수리, PLC 프로그램 구조 파악, 개선 검토를 지원하는 자료와 관리 프로그램을 만든다. 기존 HMI는 설비와 자료를 찾는 화면으로 활용하고, 시뮬레이터는 원리 이해·고장 재현·개선안 검증을 지원하는 도구로 구성한다.

같은 날 사용자가 설비별 입출력·동작 조건·운전 순서·이상 처리·근거를 정리하는 전체 설비 제어 명세와 후속 HMI 시뮬레이터 작업도 진행하도록 확인했다. 제어 명세는 위 목적을 수행하는 공통 기준으로 사용한다.

같은 날 사용자가 “전부 한곳의 html로 제어할 수 있도록”, “올인원 프로그램으로 만드는 게 목표”라고 확정했다. 사용자 화면의 단일 진입점은 index.html이다. 선택한 설비를 유지하면서 매뉴얼·수리·I/O·HMI·제어 명세·도면·래더·시뮬레이터·시험·확인 대장·개선 메모를 같은 작업실에서 사용한다. 여기서 제어는 웹 프로그램의 기능과 자료 탐색을 뜻하며, 실제 PLC 운전 통신 기능을 구현한 것으로 취급하지 않는다.

SEJIN 공정 다이어그램의 **디코팅 시안에 배치된 23개 설비를 최우선 상세 작업 범위**로 정한다. BC01·FN04를 첫 상세 사례로 사용한다. 전체 248개 관리 항목은 유지하고, 우선 설비의 운전에 필요한 배치도 밖 인터록도 관련 근거로 분석한다. 본체·모터·하위 부품은 구분하며 이름이나 역할의 유사성만으로 실물 동일성을 확정하거나 설비를 병합하지 않는다.

## 1. 설비별 매뉴얼

- 설비의 역할, 공정 연결, 구성품, 정상 운전과 정지·재기동 조건을 설명한다.
- 물리 I/O, 내부 상태, HMI 표시, 설정값, 알람을 구분한다.
- 각 설명에 도면 개정·FG/PDF 페이지·PLC 블록·네트워크·심볼을 연결한다.
- 점검 항목, 점검 방법, 정상 판단 기준과 근거를 기록한다. 근거가 없는 수치와 주기는 확인 항목으로 둔다.
- 주설비·계측·외부 연동·공통 기능·하위 구성품을 모두 대상으로 한다. 예비·삭제·과거 명칭의 상태도 별도 관리한다.

## 2. 고장 진단과 수리

설비별 진단표는 다음 순서로 구성한다.

| 단계 | 필요한 내용 |
| --- | --- |
| 증상과 발생 조건 | 기동 불가, 운전 중 정지, 출력 후 무응답, 센서 불일치, 계측값 이상 등 실제 증상과 모드 |
| 확인 신호 | 운전 요청 → 허가·인터록 → PLC 출력 → 현장 응답 → 피드백·알람의 예상값과 관찰값 |
| 프로그램 위치 | 해당 조건을 읽거나 쓰는 블록·네트워크, 타이머, Set/Reset 및 관련 상위 조건 |
| 전기·기계 확인 | 해당 FG/PDF·단자·릴레이·퓨즈·코일·센서·구동부와 필요한 확인 방법 |
| 판단과 조치 | 관찰 결과별 원인 후보와 조치, 추가 확인이 필요한 경우의 다음 단계 |
| 복구 검증 | 원인 해소, 요청·허가·피드백 정상화, 알람 복귀 조건과 재발 여부의 증거 |

단자 번호·정상 극성·허용값은 원문과 현장 근거로 확인한다. 일반 점검 절차와 특정 설비에서 확인된 조건을 구분한다. 알람을 리셋한 것만으로 수리 완료로 판단하지 않는다.

## 3. PLC 프로그램 구조 파악

- OB·FC·FB·DB 목록과 역할을 정리한다.
- 블록 호출 관계, 호출 조건, 주기 및 초기화 경로를 분석한다. 검색 색인의 순서를 실행 순서로 사용하지 않는다.
- 신호별 읽는 위치와 쓰는 위치를 구분하고, 복수 쓰기·Set/Reset·재시작 시 기억 상태를 추적한다.
- 공통 허가, 자동 기동·정지, 유지보수 모드, 알람·리셋, 계측 환산, PID, 필터 세정, 외부 연동을 설비 로직과 연결한다.
- 미해석 참조와 호출 조건은 근거 위치와 함께 남기고 TIA에서 확인할 항목으로 관리한다.

산출물은 프로그램 구조도, 블록 역할표, 신호 읽기·쓰기 대장, 설비별 제어 흐름 설명이다. 현재 제공되는 관련 네트워크 목록을 호출 구조도나 실행 순서 검증 결과로 간주하지 않는다.

## 4. 근거에 따른 개선 검토

개선 후보마다 다음 내용을 기록한다.

| 항목 | 기록 내용 |
| --- | --- |
| 문제 또는 불편 | 발생 조건·증상·운영 영향과 관련 근거 |
| 현재 동작 | 현행 로직·주소·설정·호출 조건 |
| 변경안과 이유 | 수정할 블록·조건·표시·진단 정보와 기대 효과 |
| 영향 범위 | 다른 설비·공통 조건·알람·재기동·인터페이스·데이터 |
| 검증 방법 | 시험 입력·시간 조건·기대 결과·관찰 결과·버전 |
| 복원 방법 | 원본 백업·변경 이력·되돌릴 대상 |
| 진행 상태 | 후보 → 검토 → 시험 → 적용 → 적용 후 확인 |

도면·주석·주소의 불일치나 deleted/SPARE 표기만으로 프로그램 오류를 확정하지 않는다. 분석 결과와 개선 후보, 실제 적용 및 적용 후 검증을 각각 구분한다.

## 5. HMI와 시뮬레이터의 역할

HMI에서 설비 또는 알람을 선택하면 매뉴얼·진단 절차·I/O·관련 래더·도면·작업 이력으로 이동할 수 있도록 구성한다. 시뮬레이터는 센서 상태 변화, 고장 발생, 시퀀스 전환, 리셋·재기동과 개선 전후 동작을 비교하는 용도로 사용한다.

원본에서 확인된 동작과 가정한 장치 응답·공정 특성을 표시한다. 시뮬레이터 결과, TIA 시험 결과, 현장 확인 결과는 각각 기록한다. 실제 PLC 프로그램 변경과 운전 조작은 별도 실행 작업으로 관리한다.
