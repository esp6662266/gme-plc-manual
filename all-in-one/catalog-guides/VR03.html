설비와 자료의 소유 경계

  • `registers/equipment.json`의 VR03행은 motor, FG61, parent 빈값, 별칭 빈 배열이다. P&ID `PID_1684n002I.pdf` p1 실제 렌더는 CY-02·CY-04·CY-05 하부가 SC-01로 모이고 그 출구에 VR-03/M37이 붙은 관계를 보여 준다. M37 표기는 0.55 kW 440 V다. 이 도면 관계를 VR03이 특정 CY 본체의 PLC 소유자라는 증거로 바꾸지 않는다. P14 ‘2사이클론’ 실물 식별도 해결하지 않는다.
  • `Electrical_Rev2.pdf` FG61/PDF62의 제목은 `ROTARY VALVE VR-03`, 모터는 M37, 0.55 kW/1.25 A다. 상단은 THREE-PHASE LINE 440V 60Hz다. 직접기동 회로에 전용 인버터·속도 지령·아날로그 전류/PID·엔코더는 나타나지 않는다. **검토한 직접기동 경로에서 해당 제어는 비해당**이며 현장에 추가 장치가 전혀 없다는 단정은 아니다.
  • SC01은 별도 모터 M28, VR03은 M37이다. SC01이 VR03의 처리 응답을 읽어 요청을 해제하는 의존성은 있으며, 두 모터·고장을 한 장치로 병합할 근거는 아니다.
  • FN04 예고장은 여섯 처리 응답을 공동으로 읽는다. Tag_126 90분은 VR03 전용 고장 지연 Tag_75 2초와 기능·소유가 다르다. FN04의 속도·인버터·보호값을 VR03에 배정하지 않는다.
  • P&ID 도번1684n002의 원 작성일은 06/04/2011, 판 I 변경일은 15/01/2013이다. 전기 검토 시트에는 기본 날짜27.05.2024가 있다. 해당 FG61/121/140/254의 하단에서 별도 Rev2 날짜를 확인하지 않았으므로 파일명 Rev2만으로 각 시트에 Rev2 17.03.2025를 붙이지 않는다.
  • `Electrical_Can_Decoating_20241118.pdf` p35는 `24.11.11 first draft design`, CHECKED/APPROVED 공란이다. 문서상 경로·견적성 길이 근거이며 승인 준공도·실제 설치 길이로 확정하지 않는다. PLC 백업·P&ID·전기·시공도는 서로 시점이 다르다.

고장 Set/Reset

고장 해제와 운전 복구의 차이

고장은 LAD1966에서 M_VR_03 Reset 원인이다. Reset 버튼으로 고장 비트가 내려가는 것과 운전 요청이 다시 생성되는 것은 별도다. 요청은 자동 Set 위치·HMI 외부 쓰기·실제 실행순서와 대조해야 한다. 현장에서는 원인 제거, 보호·전원·접촉기·실제 기계 상태, 명령/응답/표시의 일치를 확인한 뒤 현장 절차에 따른 재요청과 복구 증거가 필요하다. 이 초안은 Reset이나 재기동을 직접 수행하거나 승인하지 않는다.

같은 네트워크에 Set과 Reset 쓰기가 모두 있다. 동시 조건의 최종값, 요청 재Set과 고장 Reset의 스캔 경계, 전원 재시작 시 잔존 요청은 TIA/현재 CPU 검증 전이다. 타이머·알람 비트만 잠시 해제된 상황을 복구 완료로 기록하지 않는다.
