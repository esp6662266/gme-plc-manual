# GME 올인원 프로그램 v0.4

사용자 목표: 이 프로젝트의 모든 웹 기능을 한곳에서 사용하는 올인원 프로그램.

## 시작

`index.html`이 단일 시작 화면이다. 현재 맥에서는 `http://127.0.0.1:8770/`에서 사용한다. HTML·CSS·JavaScript와 자료 폴더를 함께 배포하는 정적 웹 프로그램이다. 단일 화면에서 자료를 전환하며, 원본과 상세 문서는 별도 파일로 보존한다. 전체 폴더를 보관한다.

JavaScript 자료 번들을 포함하므로 기본 탐색은 파일을 직접 열어도 가능하다. 브라우저마다 로컬 PDF·프레임 접근 제한이 달라 HTTP 서버 사용을 권장한다. 서버 실행 예: 이 폴더에서 `python3 -m http.server 8770 --bind 127.0.0.1`.

## 사용 순서

1. 왼쪽에서 우선 23개 또는 전체 248개 목록을 선택한다. 이름·태그·I/O 주소로 검색할 수 있다.
2. 설비를 선택하면 요약·매뉴얼·진단·I/O·제어 명세·래더·호출·신호 구조·도면·시뮬레이터·시험·확인 대장을 같은 화면에서 전환한다.
3. 문서 안의 도면·네트워크 링크는 통합 자료 영역에서 열린다. 자료를 따로 열거나 인쇄하는 기능도 제공한다.
4. 시험·확인 대장은 전체 또는 선택 설비로 필터링한다. 원본 상태는 미실행·확인 대기로 유지한다.
5. 개선·작업 메모는 설비별로 현재 브라우저에 저장한다. 전체 메모를 JSON으로 다운로드할 수 있다. 브라우저 데이터 삭제나 다른 브라우저로 이동하기 전 백업한다.

태그명 일치 14개, 역할 대응 후보 4개, 대응 미확정 5개를 구분한다. 모든 실물 동일성은 미확인이다. 킬른 본체와 RD01 구동부, 팬과 모터, 댐퍼와 구동부를 같은 설비로 자동 병합하지 않는다. 미확정 항목은 근거 확인 전 가상 PLC 태그를 부여하지 않는다.

## 재생성

`build-all-in-one.py`는 원본 대장에서 가벼운 통합 자료 번들과 index.html을 생성한다. 원본 JSON·CSV·PDF·PLF·ZAP18은 변경하지 않는다. CSS·JavaScript는 assets/all-in-one.css와 assets/all-in-one.js에서 관리한다.

`build-manual.py`는 기존 전체 문서를 manual-catalog.html에 생성하고, `build-control-spec.py`는 명세 생성 후 올인원 생성기를 호출한다. 후속 재생성 시 통합 시작 화면이 기존 목록으로 덮어쓰이지 않는다. Python 빌드 스크립트가 읽는 scratch 경로는 기존 스크립트 설명을 따른다.

현재 매뉴얼 작업은 `build-workspace.py`로 재생성한다. 회로 추적·시공 참조·정적 신호 분석·공통 제어·진단 작업지·대응 작업지·개선 검토·올인원 화면을 순서대로 생성하고 시뮬레이터·모델·시험 결과 파일 5개의 해시가 변하지 않았는지 확인한다.

`build-detailed-procedures.py`는 도면·원본 조건과 연결한 진단 작업지를 생성한다. `build-circuit-guides.py`는 시각 확인한 회로 추적 자료를 생성한다. `build-signal-guides.py`는 원본 XML·식별 자료와 보존된 정적 색인을 읽어 신호 매뉴얼·CSV를 생성한다. `build-review-guides.py`는 23개 대응 작업지와 개선 검토를 생성한다. 현재 `build-program-model.py`와 `verify-virtual-plc.cjs`는 실행하지 않는다. 기존 모델·엔진·가상 시험 결과를 갱신하지 않는다.

가상 실행에서는 XML Parts 순서, 선택 네트워크 호출 순서, 500ms 가상 응답 지연과 시험 초기값을 명시한다. 이것은 실제 CPU의 시간 기반 오차·전체 프로그램·현장 회로를 대신하지 않는다. 모델 파일의 SHA-256이 바뀌면 이전 행동 시험을 현재 결과로 표시하지 않는다.

메모는 브라우저 데이터이므로 빌드·ZIP에 포함되지 않는다. 사용자가 다운로드한 메모 JSON을 별도 보관한다. 현재 메모 백업 가져오기와 서버 간 동기화는 제공하지 않는다.

PV01·PV02의 밸브·위치·현장 선택, MV01·MV03·MV06의 방향 접촉기·끝단·엔코더, BR01의 외부 인터페이스를 상세 회로 작업지로 연결했다. 신호 바로가기와 원본 심볼 참조169곳에서 해당 자료로 이동할 수 있다. 엔코더3개의 주소·채널 오프셋과 버너 전용010-390의 내부 시퀀스·현재 배선은 미확정이다. 시공도면과 OEM 회로도는 상호 참조하며 서로 대체하지 않는다.

Web Locks 지원 브라우저에서는 저장을 직렬화하며 미지원 환경은 저장 직전 비교를 사용하므로 완전한 동시 저장 보장은 아닙니다. 같은 설비의 임시 초안은 마지막 작성본이 저장될 수 있으므로 충돌한 본문을 별도로 보관한 뒤 비교합니다.
