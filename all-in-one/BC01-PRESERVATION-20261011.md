# BC01 기록 보존과 작업 재개 — v1.3.0 · 2026-10-11

BC01(P01)의 기록 이동·근거 비교와 다른 컴퓨터에서의 작업 재개를 보완했습니다. 기존 네 도구의 사용법은 [BC01-RECORD-TOOLS-20261011.md](BC01-RECORD-TOOLS-20261011.md), 작업 범위는 [ACTIVE-WORK.md](ACTIVE-WORK.md)를 함께 봅니다.

## 관찰 기록

기존 요청·최종 출력·처리 응답4행에 선택 관찰8행을 추가했습니다. 원시 입력 I0.0/I0.1/I6.2, 처리 trip wire, Tag_51(%T39), FAULT/INV/FC 알람 기억을 각각 기록합니다. 값·시각·근거는 빈칸이며 정상 극성이나 수리 완료를 자동 판정하지 않습니다. 세 원시 입력의 처리 신호 전달은 미확정으로 남깁니다. I0.0은 LAD 원시 접점 사용만 확인했고 I0.1/I6.2는 확보 LAD의 직접 참조가 없습니다. 타이머의 현재 값·경과 시간은 계산하지 않습니다. 기존 기록의 미지 행·필드와 다른22개 양식은 보존합니다.

개별 수리 기록 JSON도 note 전체 객체를 내보냅니다. 제목·본문·구분·근거·추가 메타데이터와 관찰 기록을 함께 옮깁니다. 기존 observation 중심 JSON도 가져옵니다. 구형 파일에 없었던 note 필드는 복원 시 새로 증명되지 않으므로 원래 전체 백업을 우선 보관합니다. 가져오기는 미리보기·충돌 선택·최종 저장·재열기로 확인합니다.

저장 기록 전후 비교는 관찰값뿐 아니라 저장된 단계 제목·자료 위치의 변경도 표시합니다. 저장 당시 태그명·주소·근거를 사용하고 현재 양식으로 과거 기록을 다시 해석하지 않습니다.

## 버전과 근거

JSON의 generated_with는 생성 시점의 프로그램 버전·원본 SHA256 목록32개·목록 묶음 SHA256을 표시합니다. 보고서는 생성 버전·자료수·묶음 SHA256을 표시하며 개별 해시 목록은 함께 내보낸 JSON에서 대조합니다. v1.3.0에서 새로 저장한 BC01 note의 saved_with는 그 저장 시점의 버전·묶음 해시·저장 시각입니다. 이 정보는 과거 관찰 당시의 버전이나 현재 CPU/현장 상태를 증명하지 않습니다. 구형 기록은 없는 정보를 미기록으로 표시합니다. 같은 BC01 수리 기록 화면에서 수정 버튼을 눌렀을 때 저장된 입력값이 즉시 표시되도록 재열기도 보완했습니다.

## 다른 컴퓨터에서 작업

저장소 루트 WORKSPACE-HANDOFF.md와 AGENTS.md를 먼저 읽고 Git 상태·main·VERSION.json을 확인합니다. npm build는 등록된 파일 목록과 실제 목록을 양방향 대조하고 승인 목록만 복사하며 복사 후 해시도 확인합니다. 누락·추가 파일·심볼릭 링크는 게시를 차단합니다. 개인 점검 JSON을 all-in-one에 두지 않습니다.

Python3.10+ 실행기는 Windows py -3, python3, python을 탐지하며 GME_PYTHON으로 실행 파일 경로 하나를 지정할 수 있습니다. check:python은 준비 상태 확인, verify:manual은 필수14검사·manifest·버전ZIP을 재생성하는 명령입니다. 신규 패키지 파일은 검토한 상대경로 JSON 목록을 GME_NEW_PACKAGE_FILES에 일회성으로 지정해야 합니다. 다음 실행 때는 해제합니다. Python 최적화로 검사가 생략되는 실행은 거부합니다.

## 검증과 범위

최종 검증·게시 결과는 저장소 루트 PUBLICATION_STATUS.md와 manifest의 fresh_verification_runs를 확인합니다. 현재 BC01 작업과 보존된 후속21개를 화면에서 구분합니다. 원본730·추가3·중지5자산 및 기존 기록/초안/미확정 상태를 보존합니다. 시뮬레이터 작성·수정·실행·행동 시험0, 실제 PLC·현장·보호값·SEJIN 변경0입니다. TIA 컴파일/현재CPU·실물·ABB 현행 모델/단자·정상 극성·현장 복구는 확인 전입니다.
