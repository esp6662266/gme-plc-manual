# GME OCR 검색 개선 계획

기준: main 9ee1a80, v1.26.0. 수정 원본은 all-in-one/이다. 기존 원본 PDF·330쪽 OCR 추출·중지 자산·운영 저장 키를 보존한다.

1. `build-io-search-index.mjs`의 전체 기록을 도면/I/O/OCR과 매뉴얼 본문으로 나눈다. `io-search-loader.js`는 독립 캐시·30초 제한·실패한 자료만 재시도를 제공한다. `io-search.js`는 먼저 도착한 결과와 추가 로딩/실패 범위를 명시한다. 전체 기록 재결합 일치, 중복 요청, 부분 실패, 재시도, 시간 제한을 Node 검사로 확인한다.
2. `io-search-model.js`에서 공백 있는 선번을 같은 번호로 찾고 강조한다. `8.9`, `18.9`, `8.90`과 점이 여러 개인 표기는 구분한다. OCR 좌표는 신뢰도 기준을 지키고 뷰어에서 PDF 텍스트/OCR 후보를 선택해 볼 수 있게 한다. 도면 다운로드 실패는 제한 시간 뒤 재시도할 수 있게 한다.
3. 기존 남색/청록·한글 시스템 글꼴·왼쪽 정렬을 유지한다. 검색 화면에서만 모바일 메뉴를 접어 검색창을 앞에 둔다. OCR 후보 표시는 점선과 문구로 구분하며 인식 점수를 기능 확정률로 표시하지 않는다.
4. v1.27.0으로 버전/생성기/표시/manifest를 일치시키고 기존 패키지 필수14+2검사·원본/중지 해시·새 ZIP CRC/전체파일·Node/build/CSP를 확인한다. 대표 선번·태그, OCR/PDF 위치 전환, 모바일, 부분 실패와 실제 Netlify 게시를 검증한다.

검토 초점: 부분 성공을 0건으로 오해하지 않는지, 필터 변경 중 늦은 응답이 현재 검색을 덮지 않는지, 선번이 다른 번호로 합쳐지지 않는지, 메뉴·도면 닫기 후 초점과 상태가 유지되는지. 설비 도면상충·철거 검토·PLC/현장·시뮬레이터 작업은 재개하지 않는다.
