- `0147`은 DB2.DBW0,2,4,6,8,10,12,14에 INT#0을 쓰는 8 Move다. 포함 범위는 **DB2 byte0..15**다.
- `0148`은 DB3.DBW0,2,4,6,8,10,12,14,16에 INT#0을 쓰는 9 Move다. 포함 범위는 **DB3 byte0..17**다. “모든 알람 초기화”라는 제목으로 DB3 전체 Reset을 확정하지 않는다.
- 보강 표의 고유28비트 중26개가 중첩한다. 범위 밖2개는 **ER01_run DB3.X20.1**, **Pot_MV02_OFR DB3.X24.7**이다. 이는 보강의 선정된28비트에 대한 결과이며 MV05의 다른 OFR 등 전체 알람을 망라한 목록이 아니다.

- `0149` MV02/MV05 Auto Set과 `0150` PV03 MEM_CLOSE Set이 공존한다. Word 0쓰기만으로 재시작 후 최종값0을 보장하지 않는다. ON·en/eno, 상위 OB·현재 CPU·Warm/Cold·Retain·외부/HMI/다른 Writer 우선순위는 미확정으로 남긴다.

1. **시작 백업과 전체 해시:** 현재 로컬 기준 커밋·버전·작업트리·미커밋 변경을 확인하고 시작 백업을 남긴다. 원본·추가 원본·중지 자산의 전체 목록과 SHA-256을 고정한다. 기존 사용자 기록·미지 필드·기존 완료문서를 보존한다. 위 수신10개·보강본·입력의 해시와 필수 근거 존재를 확인하고 조사 고정 커밋과 현재 기준의 차이를 기록한다.
2. **설비별 고유 근거 및 변경 영향:** 각 초안의 7영역과 네 기능 적용 상태를 확인한다. 출력 정지·알람 타이머·신호/로직 소유·전기 끝점·상충을 원본 Part/Wire/ORef/선언 및 PDF에서 독립 대조한다. 이름이나 유사 설비로 조건을 복제하지 않는다. 오류가 드러나면 관련 설비·공유 로직까지 영향을 확인한다.
3. **단일 편집과 중간 검사:** 설비별 문서·UI·링크·기록·PDF를 순차 통합한다. 중간에는 필요한 개별 검사를 한다. 공통 UI·라우팅·기록·생성기를 수정하면 BC01 전체 및 영향받는 기존 완료 설비 회귀를 유지한다. 표준 §6의 PC1280/모바일390, 저장·재열기·복원, 미지 필드 보존 등 적용 검사를 생략하지 않는다.
4. **중복 절감 조건:** 공통 근거는 원본 위치·조건·호출 관계의 동일성을 확인한 뒤 한 번 검토하고 설비별 차이를 확인한다. 검토 재사용은 입력·코드·환경·검사 버전 및 결과 근거가 모두 동일한 경우만 허용한다. 해시 일치는 의미 검토 대체물이 아니다. 작은 문구 수정은 묶되 핵심 논리 오류는 즉시 영향 판정한다.
5. **최종 묶음 검증과 패키지:** `verify:manual`은 단순 조회가 아니라 **14개 Python 검사와 2개 Node 검사 및 manifest·보고서·ZIP 재생성**을 한다. 최종 묶음의 마지막 수정 뒤 수행하고, 호출 경로를 먼저 확인해 금지 생성기가 실행되지 않게 한다. 필수14+2·설비별 수락검사·회귀, 원본/추가원본/중지 자산 전체 해시, 파일 목록, ZIP CRC/전체 SHA, npm test/build, CSP 검증을 생략하지 않는다. 검증 후 기능 파일을 바꾸면 영향 검증과 패키지를 갱신한다.
6. **실제 게시의 정확한 커밋 검증:** 검증한 소스·패키지·GitHub 실제 커밋·Netlify commit_ref/ready·실제 게시 파일/UI가 동일 결과물로 이어지는지 확인한다. 기능 커밋과 기록 커밋이 별개이면 둘 다 기록한다. 예정 커밋·push·ZIP 생성·ready 표시 하나만으로10개 게시 완료를 선언하지 않는다.
7. **실패 항목 격리와 집계:** 실패 ID·단계·원인·영향·필요 자료·재개 조건을 분리한다. 공유 변경의 영향이 격리되지 않으면 묶음 게시를 통과시키지 않는다. 유효한 앞 단계 결과는 보존하고 실패 지점부터 재개하되 바뀐 입력/코드/환경/검사는 다시 확인한다. 무근거 단언 완화·시험 삭제로 통과시키지 않는다. 실제 게시 확인된 고유 ID만 신규0에서 누적하고 기존21문서와 구분한다.
8. **수신 회신:** 수신한10개/누락파일, 현재 기준 커밋, 진행 단계, 남은 검증, 미확정/상충/격리 ID, 최종 검증 보고서·ZIP 해시·실제 게시 정확 커밋/배포 근거 및 신규 게시 수를 회신한다. 단계별 시작·종료·대기·재작업 실측 시간을 남기고 예상 절감률을 실적으로 쓰지 않는다.

## 이 인계에서 확인한 것과 실행하지 않은 것

실제 전달 대장의 첫10개 순서/Library ID, 원초안 핵심·보강 범위, 현재 파일 SHA-256을 확인했다. 원초안·보강문·원본 저장소·진행 JSON은 수정하지 않았다. 이 인계와 원문 그대로의 문서 전달용 ZIP만 작성했다. 로컬 통합, 매뉴얼 검증 명령 실행, 매뉴얼 배포 패키지 생성, 게시, 외부 전송·업로드는 수행하지 않았다. 문서 수신은 실행·게시 완료 증거가 아니다.
